## 1. Что проверить на витрине

### 1.1. Посадочные каталога

Открыть несколько URL вида `/catalog/{slug}`, например:
- https://prod.mobiz.by/catalog/fruktovye-muzhskie-duhi

Проверить:
- [ ] страница открывается (не 404);
- [ ] есть H1 и текст посадочной (не пустая витрина);
- [ ] список товаров соответствует полу/фильтрам посадочной;
- [ ] в адресе нет «лишних» `?attr_...` как единственного канона — страница живёт по `/catalog/{slug}`;
- [ ] при доп. фильтрах поверх посадочной поведение адекватное (список меняется; SEO может стать noindex — это ок).

Список всех slug — в админке (см. раздел 2).

### 1.2. Проверка батч-кода

URL: https://prod.mobiz.by/proverka-batch-coda

Проверить:
- [ ] страница открывается, есть текст «что такое код / где найти / что код не доказывает подлинность»;
- [ ] в форме есть список брендов + пункт «Другой бренд»;
- [ ] **Versace** + код из 7 цифр (например `1234567`) → ориентировочный год / approximate;
- [ ] **Chanel** → «формат распознан», без точной даты;
- [ ] **Другой бренд** → «пока не поддерживается», не ошибка сервера;
- [ ] под результатом есть дисклеймер (не проверка подлинности);
- [ ] блок «Помогите улучшить проверку» для обычного бренда открывается (дата + согласие).

Не ожидать: дату по Antonio Banderas, Gucci и большинству брендов — в пилоте узкое покрытие.

## 2. Админка — как работать с новым

Базовый URL админки: `https://prod.mobiz.by/admin/...` (нужна учётка админа).

### 2.1. Посадочные каталога

Путь: **Контент → «Посадочные каталога»**  
или напрямую: `/admin/catalog-landings`

| Действие | Куда |
|---|---|
| Список | `/admin/catalog-landings` |
| Создать | `/admin/catalog-landings/create` |
| Редактировать | `/admin/catalog-landings/{id}/edit` |

Поля:
- **slug** — адрес `/catalog/{slug}`;
- **пол** — female / male / unisex (или пусто);
- **фильтры** — атрибут → значения (как в каталоге);
- **H1, SEO title/description, HTML-контент**;
- **активна** — выкл. = посадочная не на витрине и не в sitemap.

На проде сейчас **53** активных посадочных после импорта. Правки текстов в админке сохраняются; повторный импорт **без** `--force` их не затрёт.

### 2.2. Отзывы

Путь: `/admin/reviews`

- фильтр по типу: **product** / **store**;
- фильтр по статусу: **published** / **pending**;
- для pending (id ниже) — опубликовать, отклонить или ответить по обычным правилам админки.

### 2.3. Статьи

Путь: `/admin/posts` (или ваш раздел статей/новостей).  
Искать по slug из п. 1.3.

### 2.4. Батч-код

- Витрина: `/proverka-batch-coda` — для проверки сценария.
- **Отдельной страницы в админке для заявок «помогите улучшить» пока нет.**  
  Заявки пишутся в таблицу `batch_code_submissions` (API только для разработки). Правила брендов правятся в коде, не в админке.

## 4. Куда писать баги

В баге указать:
1. URL (полный);
2. что ожидали / что увидели;
3. скрин + user-agent / мобилка или десктоп;
4. для отзывов — **id**;
5. для посадочных — **slug**.

Известные ограничения (не баги части 1):
- картинки статей могут быть с домена el-parfume.by;
- батч-код поддерживает узкий набор брендов (пилот);
- редиректы el-parfume.by ещё не в бою.
